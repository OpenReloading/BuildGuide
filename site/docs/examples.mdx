# Examples

One small, complete guide per component, and the files that show it on a plain HTML page, in MkDocs and in Docusaurus. Save the JSON as `guide.json`. The [example guide](example/index.mdx) uses every key of the [data format](data-format.mdx).

Plain HTML needs a web server (the script fetches `guide.json`), for example `python3 -m http.server`, and the core files unpacked into `assets/` ([Plain HTML](core.mdx)). Replace `<version>` with the core version.

## BOM checklist

Items with a group, a name, a specification and a quantity. The component adds search, a filter for missing and done items, a tick per item, group counts, the CSV export and a print button. Live with the full example data: [BOM](example/bom.mdx).

```json title="guide.json"
--8<-- "packages/core/example/minimal/bom.json"
```

## BOM, steps and boards behind tabs

One component with a tab for the BOM, one for the steps when the data has a top-level `steps` object, and one for each board, in the order of the data (the BOM, the steps, then the boards). Only the shown tab is mounted, so a board is drawn when you open its tab. `data-board="wiring tubing"` (Docusaurus: `board="wiring tubing"`) picks tabs and their order; `bom` names the BOM and `steps` the steps. The tab is kept in the hash (`#guide=wiring`) next to the boards' own positions. Live with the full example data: [Combined](example/guide.mdx).

```json title="guide.json"
--8<-- "packages/core/example/minimal/all.json"
```

## Several components on one page

Place them one after the other, each board once per page. The [All components](example/all.mdx) page shows the BOM, wiring and tubing together; its guide data holds `bom` and both boards. A board is either standalone or in a tab, not both on one page.
