# BuildGuide

<p className="bg-lead">A parts checklist plus wiring and tubing diagrams for your build documentation, from one data file. Readers tick off each part and connection as they build, and the ticks stay in their browser.</p>

<p className="bg-actions"><Link className="button button--primary" to="/example/">Open the live example</Link> <Link className="button button--secondary" to="#getting-started">Read the docs</Link></p>

For people who document a hardware build on a MkDocs, Docusaurus or plain HTML site.

<ul className="bg-facts">
<li>MIT license</li>
<li>Plain JavaScript and CSS</li>
<li>No requests outside the site</li>
</ul>

<h2 id="progress">Progress stays in the browser</h2>
<p>Ticks are saved in <code>localStorage</code> under the <code>storage</code> key of the guide. A tick belongs to one exact connection (number and both ends): changing an end clears it. Export downloads <code>&lt;storage&gt;.json</code>, Import replaces the saved progress from such a file and Reset removes it. Import and reset act at once: the status line of the component says what happened and offers <code>Undo</code>.</p>
</div>

## Getting started

| Your site | Use | Release |
|---|---|---|
| [Plain HTML](core.mdx) | browser components, JSON Schema and check CLI for any static site | `core-v*`: `buildguide-<version>.tar.gz` (earlier versions also on GitHub Packages) |
| [MkDocs](mkdocs.mdx) | `<div data-buildguide="...">` in Markdown, data checked at build time | `mkdocs-v*`: wheel and sdist |
| [Docusaurus](docusaurus.mdx) | `<BuildGuide view="..."/>` component, data checked at build time | `docusaurus-v*`: `.tgz` (earlier versions also on GitHub Packages) |

## Then
